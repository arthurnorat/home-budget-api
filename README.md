# Home Budget API

REST API for shared household expense tracking between two users.

This backend is built with Spring Boot, stores its data in Firestore and runs
on Google Cloud Run. It is shared by a web client, a macOS client, and
dedicated iOS and Android clients for quick expense entry.

## Live demo

- Web app: [home-budget-web-ten.vercel.app](https://home-budget-web-ten.vercel.app)
- API: [home-budget-api-689350097433.southamerica-east1.run.app](https://home-budget-api-689350097433.southamerica-east1.run.app)

## Features

- Create, list, update and delete expenses
- List expenses by month
- Classify expenses as fixed or variable
- Register and query monthly income
- Share the same data between two known users

There is no authentication yet; it is planned (Firebase Auth). The API is
public and meant for private use between two known users.

## Stack

- Java 21
- Spring Boot 3.5
- Spring Web
- Bean Validation
- Cloud Firestore (native Java SDK)
- Firestore emulator for local development
- Google Cloud Run for hosting, built from source with Google buildpacks

## Architecture

- Layered REST API: controllers only handle HTTP, business logic lives in
  services, data access goes through repositories built on the Firestore SDK;
  entities and DTOs are kept separate.
- Domain exceptions are mapped to HTTP responses in a single
  `@RestControllerAdvice`; a Firestore failure answers `503`.
- Code organized by feature package (`expense`, `income`).

## Data model

Firestore stores collections of documents, with no tables.

### `expenses`

The document id is the expense UUID, generated by the application.

| Field | Type | Note |
| --- | --- | --- |
| `description` | string | Required |
| `amount` | number | Amount in cents |
| `date` | string | Expense date in ISO 8601 (`YYYY-MM-DD`), stored as text |
| `category` | string | `FIXED` or `VARIABLE` |
| `createdAt` | timestamp | Generated automatically |

### `monthly_income`

The document id is the month in `yyyy-MM` format, so a month never has two entries.

| Field | Type | Note |
| --- | --- | --- |
| `amount` | number | Monthly income in cents |

## API

- `POST /expenses` — create an expense
- `GET /expenses?month=yyyy-MM` — list expenses for a month (defaults to the current month)
- `PUT /expenses/{id}` — update an expense
- `DELETE /expenses/{id}` — delete an expense
- `GET /income?month=yyyy-MM` — get the month's income
- `PUT /income?month=yyyy-MM` — save or update the month's income

Full request/response contract: see the project's `CLAUDE.md`.

## Conventions

- Monetary values are stored in cents.
- Dates are exchanged in ISO 8601.
- Code and variables are in English.
- Commits must be written in English.

# Home Budget API

API REST para controle de gastos domésticos compartilhado entre dois usuários.

Este backend é feito em Spring Boot, guarda os dados no Firestore e roda no
Google Cloud Run. É compartilhado por um cliente web, um cliente macOS, e
clientes dedicados em iOS e Android para inserção rápida de gastos.

## Demo em produção

- App web: [home-budget-web-ten.vercel.app](https://home-budget-web-ten.vercel.app)
- API: [home-budget-api-689350097433.southamerica-east1.run.app](https://home-budget-api-689350097433.southamerica-east1.run.app)

## Funcionalidades

- Criar, listar, atualizar e remover gastos
- Listar gastos por mês
- Classificar gastos como fixos ou variáveis
- Registrar e consultar entrada mensal
- Compartilhar os mesmos dados entre dois usuários conhecidos

Ainda não há autenticação; ela está planejada (Firebase Auth). A API é
pública e de uso privado entre dois usuários conhecidos.

## Stack

- Java 21
- Spring Boot 3.5
- Spring Web
- Bean Validation
- Cloud Firestore (SDK nativo para Java)
- Emulador do Firestore para desenvolvimento local
- Google Cloud Run para hospedagem, com build a partir do código pelos buildpacks do Google

## Arquitetura

- API REST em camadas: controllers só lidam com HTTP, lógica de negócio nos
  services, acesso a dados via repositories construídos sobre o SDK do
  Firestore; entidades e DTOs ficam separados.
- Exceções de domínio são mapeadas para respostas HTTP num único
  `@RestControllerAdvice`; uma falha do Firestore responde `503`.
- Código organizado por feature (`expense`, `income`).

## Modelo de dados

O Firestore guarda coleções de documentos, sem tabelas.

### `expenses`

O id do documento é o UUID do gasto, gerado pela aplicação.

| Campo | Tipo | Observação |
| --- | --- | --- |
| `description` | string | Obrigatório |
| `amount` | número | Valor em centavos |
| `date` | string | Data do gasto em ISO 8601 (`YYYY-MM-DD`), guardada como texto |
| `category` | string | `FIXED` ou `VARIABLE` |
| `createdAt` | timestamp | Criado automaticamente |

### `monthly_income`

O id do documento é o mês no formato `yyyy-MM`, então um mês nunca tem duas entradas.

| Campo | Tipo | Observação |
| --- | --- | --- |
| `amount` | número | Entrada mensal em centavos |

## API

- `POST /expenses` — cria um gasto
- `GET /expenses?month=yyyy-MM` — lista os gastos do mês (padrão: mês atual)
- `PUT /expenses/{id}` — atualiza um gasto
- `DELETE /expenses/{id}` — remove um gasto
- `GET /income?month=yyyy-MM` — busca a entrada do mês
- `PUT /income?month=yyyy-MM` — salva ou atualiza a entrada do mês

Contrato completo de request/response: ver o `CLAUDE.md` do projeto.

## Convenções

- Valores monetários são armazenados em centavos.
- Datas são trafegadas em ISO 8601.
- Código e variáveis ficam em inglês.
- Commits devem ser escritos em inglês.
